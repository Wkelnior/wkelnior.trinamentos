# OPUS 5.5 — PREMIUM MOTION VIDEO / SKILL DEMONSTRATION

## PROJECT OBJECTIVE

Create a **high-retention vertical motion-design video** for Instagram Reels using the attached narration audio as the **master timeline**.

The purpose of the video is to demonstrate, visually and in real time, the difference between:

1. asking Claude for something in a generic way;
2. actually directing Claude with intentional creative commands;
3. using a structured skill/workflow to turn those commands into premium motion design.

The video must feel like a **live demonstration of creative direction**, not like a tutorial made from static slides.

The viewer should constantly feel:

> “Everything he says is happening on screen right now.”

The final CTA invites the viewer to comment **SKILL** to receive the same structure/skill used in the video.

---

# 1. MASTER RULE: AUDIO CONTROLS EVERYTHING

Use the **attached voice/narration audio** as the absolute master timeline.

DO NOT regenerate, replace, clone, reinterpret or synthesize the narration.

Use the original attached audio exactly as provided.

Before creating any visual scene:

1. analyze the full audio;
2. detect sentence boundaries;
3. detect pauses;
4. detect emphasis;
5. detect changes in energy;
6. detect words that describe visual actions;
7. create timeline markers for every important phrase.

Every major animation must be synchronized to the spoken words.

If the narration says:

> “Cria um quadrado.”

The square must appear exactly at that moment.

If the narration says:

> “Agora transforma em um círculo.”

The transformation must begin on the word **“transforma”**.

If the narration says:

> “Faz pontas surgirem.”

The points must physically grow out of the object.

If the narration says:

> “Joga tudo pro céu...”

The camera and object must accelerate upward.

If the narration says:

> “e explode.”

The explosion must happen precisely on **“explode”**.

The visuals must feel choreographed by the voice.

## SCENE 01 — “DAR VIDA”

Narration concept:

> “Eu quero te ensinar a dar vida às suas animações no Claude.”

### Visual

Start with almost complete darkness.

A thin cyan point appears.

From the point, reveal the word:

**ANIMAÇÃO**

Initially, the word should look static and lifeless.

When the narration reaches **“dar vida”**:

- inject cyan energy into the typography;
- add depth;
- letters move independently;
- subtle 3D extrusion appears;
- particles emerge;
- the environment gains parallax;
- camera begins moving.

The phrase visually comes alive.

Optional visual statement:

**DAR VIDA**

Use it only if it improves rhythm.

---

## SCENE 02 — GENERIC PROMPT

Narration concept:

> “Porque não adianta simplesmente copiar uma skill e falar: Claude, cria um vídeo pra mim.”

### Visual

Transition from the typography into a stylized Claude-like prompt interface.

Do not reproduce trademarked UI pixel-for-pixel.

Create a custom premium AI command interface.

Show the command being typed:

> Claude, cria um vídeo pra mim.

The interface processes.

Then output something intentionally generic:

- smartphone centered;
- flat frontal angle;
- generic dashboard;
- simple fade;
- basic title;
- no depth;
- no strong motion.

A subtle label appears:

**GENÉRICO**

The visual should communicate:

“Yes, it works — but this could belong to anyone.”

---

## SCENE 03 — “IGUAL PARA TODO MUNDO”

Narration concept:

> “Ele vai criar. Mas provavelmente vai fazer algo genérico, igual faria para qualquer outra pessoa.”

### Visual

Duplicate the generic smartphone.

Then duplicate it again.

Then again.

Build a wall/grid of identical phones.

Use a quick camera pullback to reveal many copies.

Every version should feel nearly identical.

This visually represents generic AI output.

At the exact moment the narration finishes the thought, collapse all phones back into a single point.

---

## SCENE 04 — THE TURN

Narration concept:

> “Agora olha o que acontece quando você aprende a comandar.”

### Visual

Momentary pause.

The environment becomes cleaner.

One cyan focus point remains centered.

A single smartphone emerges from it.

Camera slowly pushes forward.

Typography:

**COMANDAR**

Make the word feel deliberate and powerful.

This is the turning point of the video.

## SCENE 05 — SIMPLE REQUEST VS CREATIVE DIRECTION

## SCENE 09 — KPIs LEAVE THE SCREEN

Narration concept:

> “E, enquanto ele gira, faz os principais indicadores saírem de dentro da tela e acompanharem o movimento.”

This is one of the HERO moments.

Example cards:

- FATURAMENTO
- CLIENTES
- CONVERSÃO
- RESULTADOS

If the attached product/system contains real KPI names, use the real ones instead.

Cards should:

1. originate from inside the display;
2. cross the glass surface;
3. gain physical depth;
4. rotate into camera view;
5. orbit around the phone;
6. remain linked by subtle lines or light trails;
7. follow the smartphone's motion;
8. return or reorganize elegantly.

Use animated numbers.

Numbers should count up rapidly as they emerge.

Create hierarchy:

- one major KPI;
- secondary KPIs around it;
- subtle supporting data.

Do not clutter the frame.

# 14. CONTINUOUS VISUAL ANCHOR

Whenever possible, maintain a tiny cyan focal element across transitions.

This can be:

- a glowing point;
- a small orb;
- a data node;
- a cursor-like light point.

The point can become the origin of the next animation.

Examples:

- typography collapses into the point;
- point becomes smartphone;
- smartphone collapses into point;
- point becomes square;
- square becomes circle;
- explosion particles converge back into point;
- point becomes CTA.

This creates continuity and subtly guides the viewer's eye through the entire video.

The anchor should never become distracting.

# 15. CAMERA LANGUAGE

Use a virtual camera as part of the storytelling.

Preferred camera behavior:

- controlled push-ins;
- short pullbacks;
- 3D orbiting;
- parallax;
- small perspective changes;
- depth transitions;
- camera-through-object transitions;
- match cuts;
- object-follow camera movements.

Avoid:

- random zooming;
- constant handheld shake;
- meaningless rotation;
- hyperactive camera movement.

Every camera move must have a reason.

---

# 16. TRANSITIONS

Transitions must be generated from the existing visual element whenever possible.

Examples:

- text becomes a UI panel;
- UI panel becomes smartphone screen;
- smartphone edge becomes a line;
- line becomes a square;
- square morphs into circle;
- explosion particles become typography;
- typography becomes skill document;
- skill document collapses into CTA.

Avoid generic transition packs.

Do not use random wipes, zoom presets or repeated blur transitions.

---

# 17. MOTION QUALITY

- anticipation;
- acceleration;
- deceleration;
- inertia;
- overshoot when appropriate;
- follow-through;
- secondary motion;
- physical continuity;
- visual hierarchy.

Nothing should move at constant linear speed unless intentionally mechanical.

Use professional easing curves.

Prefer animation curves that feel physical and cinematic.

# 22. RETENTION RULES

The first 3 seconds must contain meaningful visual change.

Never keep the same composition static for too long.

Every few seconds, change at least one major visual variable:

- scale;
- depth;
- camera;
- object;
- typography;
- lighting;
- layout;
- geometry.

However, do not create chaos.

Retention comes from **progression**, not random movement.

Use open loops:

- start a transformation before fully explaining it;
- reveal the result exactly as the narration reaches it;
- let the next scene emerge from the previous scene.
